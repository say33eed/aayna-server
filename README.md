# AAYNA API

Backend foundation for **AAYNA — Looking good, simplified.**

## Stack

Node.js 22 LTS, Express 4, TypeScript, MongoDB native driver, CORS, Helmet.

## Local setup

```powershell
npm install
Copy-Item .env.example .env
 # Edit .env and set MONGODB_URI before starting
npm run dev
```

Open `http://localhost:5000/health`.

## Validation

```powershell
npm run typecheck
npm run build
npm start
```

## Environment variables

- `MONGODB_URI`: MongoDB connection string; database name is `aayna`.
- `PORT`: local port; deployment platforms may inject their own port.
- `CLIENT_ORIGIN`: comma-separated allowed browser origins, without trailing slashes. Set `https://aayna-client.vercel.app` in production; add any other real frontend origins only when needed.
- `NODE_ENV`: `development` or `production`.

Never commit `.env` or credentials. `.env.example` contains no secrets.

## Deploy (Render Web Service)

1. Push this folder to a **separate** GitHub repository named `aayna-server`.
2. Create a Render Web Service from that repository, Node runtime.
3. Set build command `npm ci --include=dev && npm run build` (commit `package-lock.json` generated by `npm install`).
4. Set start command `npm start`.
5. Set `NODE_ENV=production` and `CLIENT_ORIGIN=https://aayna-client.vercel.app`.
6. Do not set `PORT` unless your host requires it; the platform's injected port is used.
7. Verify `https://YOUR-SERVER-URL/health` returns a JSON success response.

MongoDB connectivity is implemented. Better Auth, JWT validation, appointment routes, and Stripe are **not yet implemented**. The planned main collections are users (Better Auth), services, appointments, and transactions. Collections will be created as their features are implemented. Set MONGODB_URI in Render before deployment. The /health endpoint reports API reachability and database ping separately. A disconnected database does not cause the web service to restart.
